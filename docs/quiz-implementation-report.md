# Monsters’ Party: как устроен квиз

Актуальная реализация на 20 октября 2026 года. Это описание работающей версии, а не сценарий исходного экспорта Genially. Документ можно использовать как образец при подготовке следующей учебной игры.

## Устройство проекта

Это отдельное приложение на React, TypeScript и Vite. Плеер Genially не используется; все изображения, записи и видео лежат в `public/assets/`. Проект содержит 43 слайда, шесть монстров и шесть слов о еде. Список экранов и интерактивные правила находятся в `src/App.tsx`, данные персонажей и продуктов — в `src/data/originalGame.ts`, внешний вид — в `src/styles.css`. `src/hooks/useAudioManager.ts` управляет звуком, `src/hooks/useGameSave.ts` — сохранением номера слайда и настройки звука.

Это пока **не универсальный конструктор квизов**: новую тему с теми же механиками можно оформить заменой материалов и данных, но иной порядок экранов или новый тип задания потребует правки компонентов.

| Слайды | Содержание |
| --- | --- |
| 1–4 | Обложка, дом, знакомство с монстрами, вступительное видео. |
| 5–6 | Почтовый ящик и письмо — вход в игру с приглашениями. |
| 7–17 | 11 раундов: прослушать приглашение и выбрать говорящего монстра. |
| 18 | Повторить игру или продолжить. |
| 19–24 | Видео ведьмы, реплики «How are you?», видео скелета и кафе, шесть слов о еде, Memory. |
| 25–38 | Кафе: вступление, шесть пар «видео заказа → выбор продукта», заключительное видео. |
| 39–40 | Переключатель слов с произношением и Dobble на двух игроков. |
| 41–43 | Видео тролля, песня, финал. |

Номера в таблице начинаются с 1; индекс `scene` в коде начинается с 0. Между экранами переводят кнопки и функция `go(index)`. На чёрном поле слева при наведении открывается меню всех 43 слайдов для быстрого перехода преподавателя.

## Правила игр

**Приглашения.** Сначала нажимают на ящик, затем на письмо. Формируются 11 случайных раундов: все шесть монстров в первом цикле и пять во втором. Нажатие на саму картинку приглашения запускает запись `*-welcome.wav`; после этого активируются портреты в порядке тролль, скелет, ведьма, вампир, привидение, ворон. Ошибка запускает `*-boo.wav` и краткую подсветку, правильный ответ — `*-br.wav` и переход к следующему раунду. `*` здесь означает монстра текущего приглашения. Сейчас выбор становится доступен сразу после **нажатия**, а не после окончания записи; если в следующем проекте необходимо именно дослушать голос, переход надо привязать к событию `ended`.

**Слова и Memory.** Шесть слов — `melon`, `toast`, `bacon`, `juice`, `peach`, `roll`; у каждого есть картинка и произношение. В Memory 12 перемешанных карточек: шесть пар «картинка + написанное слово». При открытии слова звучит его запись.

**Кафе.** Для каждого монстра в `cafeScenes` заданы фон, видео реакции и правильный продукт: ведьма→peach, привидение→toast, ворон→bacon, вампир→juice, тролль→roll, скелет→melon. Ошибка и успех сопровождаются разными репликами, после успеха появляется видео реакции. На слайде 39 переключатель случайно выбирает одно из шести слов без немедленного повтора и произносит его.

**Dobble.** Два игрока, по две жизни, пять раундов. На каждой карточке по пять символов из монстров и продуктов; ровно один символ совпадает. Верный выбор приносит очко игроку, ошибка снимает жизнь и отдаёт очко сопернику. В конце отображается победитель или ничья. Это набор пар карточек с одним общим символом, не полный математический комплект классического Dobble.

## Медиа, экран и сохранение

Игра центрируется в кадре 4:3, поэтому на широком проекторе остаются чёрные поля по бокам. Фоны и активные зоны расположены в процентах от размера кадра. Видео — локальные MP4; анимированные персонажи используют WebM/WebP. Звук предыдущей реплики останавливается при запуске новой, а необходимые файлы подгружаются для активного слайда, не все сразу.

После оптимизации набор медиа уменьшен примерно с 192,3 до 155,3 МБ: 15 видео перекодированы без изменения разрешения и звуковой дорожки, три PNG уменьшены с идентичными пикселями. Видео сохраняют высокую визуальную точность, но не являются побитово без потерь. Оригиналы лежат локально в игнорируемом `archive/`.

`localStorage` под ключом `monsterPartyOriginalSave_v2` хранит только номер слайда и включённость звука. Порядок приглашений, открытые карты Memory и результат Dobble после перезагрузки не восстанавливаются. Перемешивание реализовано через `sort(() => Math.random() - 0.5)`; для следующего проекта с требованиями к равномерности и воспроизводимости лучше использовать Fisher–Yates и сохранённый порядок раундов.

## Как повторить проект

1. Составить таблицу экранов: цель, действие игрока, варианты, правильный ответ, реакция на ошибку и успех, следующий экран.
2. Подготовить каталог материалов с едиными идентификаторами. Для каждой реплики записать отдельный файл, для каждого видео указать место в маршруте и желаемое поведение при завершении.
3. Утвердить формат кадра и проверить фон/активные зоны на реальном проекторе. Если текст встроен в изображения, предусмотреть отдельные версии для другого языка.
4. Сделать один полный раунд каждого типа, проверить правильный и неправильный путь, затем заполнить остальные данные в `originalGame.ts`.
5. Отдельно решить, сохраняется ли прогресс **внутри** игры после перезагрузки. Текущий проект сохраняет только слайд.
6. Собрать проект (`npm ci`, `npm run build`) и проверить его в браузере; скрипты `scripts/check-media-optimization.mjs` и `scripts/check-final-slides.mjs` проверяют часть действующего маршрута. Старые `scripts/smoke-test.mjs` и `docs/game-flow.md` относятся к предыдущей версии и не должны использоваться как точное описание новых правил.
7. Настроить хостинг под базовый путь из `vite.config.ts`. Для нового репозитория путь `/monparty/` нужно заменить на его имя или настроить другой адрес.

Для действительно переиспользуемого конструктора следующий технический шаг — вынести последовательность экранов и вопросы из условий в `App.tsx` в типизированную конфигурацию, оставив каждую механику отдельным компонентом.
